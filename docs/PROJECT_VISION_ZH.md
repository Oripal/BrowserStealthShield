# BrowserStealthShield — 项目定位与最小可行范围 V0.3

**日期：2026-10-18**  
**英文：Browser Geolocation Privacy Guard**  
**中文：浏览器地理位置隐私保护工具**

## 一、核心使命

帮助用户减少网页对真实位置相关信息的**非预期获取与暴露**。项目从早期“隐藏 CJK 特征的实验插件”转向**原生权限控制 + WebRTC 地址隐私 + 范围明确的诊断**。

项目不再按“通用浏览器隐私与隔离诊断工具箱”路线建设，不做四模块大平台。

## 二、必须区分三种位置来源

| 信息来源 | 能做什么 | 不能承诺什么 |
|---|---|---|
| 精确位置（Geolocation API） | 经用户选择，利用 Chrome 原生内容设置拒绝位置请求 | 不阻止网站依据 IP 推断大致地区 |
| WebRTC ICE 地址 | 查看 / 可选调整浏览器原生 WebRTC IP 处理策略，检查意外地址暴露 | 不保证任意协议、浏览器版本和网络组合都无泄漏 |
| 出口 IP 与间接线索 | 说明浏览器连接的 IP、时区、语言等可能被观察；给出诊断建议 | 扩展不能从服务器端抹除连接 IP，也不保证完全不可定位 |

**边界原则：** 防止未经授权的精确位置读取与减少意外地址暴露，不等于隐藏或伪造访问所在地。项目不承诺绕过第三方平台的地域访问限制。

## 三、第一版 Chrome MVP

1. **Location Permission Guard**
   - 只读显示浏览器地理位置权限状态。
   - 用户选择“阻止”时，使用 Chrome 提供的内容设置机制进行控制；显示影响范围，允许恢复原值。
   - 不在页面主世界 Hook `navigator.geolocation`。

2. **WebRTC Address Privacy**
   - 只读显示 `chrome.privacy.network.webRTCIPHandlingPolicy` 当前设置。
   - 提供风险说明与用户主动开启的可选限制；指出可能影响实时音视频和 P2P 连接。
   - 显式展示限制无法改变 HTTP 请求的出口 IP。

3. **受控测试**
   - 在自有测试页面检测位置权限拒绝行为，并用用户主动触发的 WebRTC 测试验证实际可见地址。
   - 外部 STUN/网络探针可能需要联网；如果使用，必须事前说明并由用户主动触发。
   - 默认不收集个人身份、精确经纬度、Cookie、账号凭证或唯一指纹原始数据。

## 四、严格非目标

- 不做多 Profile、Containers 的完整隔离测试套件。
- 不做代理服务、VPN、IP 轮换或伪造地域、时区、语言、设备身份。
- 不做浏览器指纹“零 Lies”欺骗性修改。
- 不修改 Windows 事件日志、系统地理位置历史或其他安全审计记录。
- 不主动扫描局域网、CLI/IDE 的系统网络路径，不实现第三方平台风险评分。
- 不宣称“绝对无法定位”“百分之百无泄漏”“永不封号”。

## 五、验收标准与测试边界

- Chrome 目标版本能够正确读取位置权限策略，并在用户主动请求后通过原生设置拒绝定位。
- 恢复原有设置后，权限状态符合预期；不会永久破坏网页地理位置功能。
- WebRTC 选项的状态可读，用户主动切换时展示正确的影响说明和恢复操作。
- 使用自有测试页面记录 Chrome 版本、测试环境、实际观察、复测次数和可能的功能副作用。
- 必须清晰说明出口 IP 仍可能暴露地理信息，不得将测试结果解释为对外不可定位。
- 没有测试数据时状态为“尚未验证”；不能把设计稿当作实测报告。

## 六、版本节奏

**V0.1：** 已提交 Chrome 扩展源码（位置权限控制、可选 WebRTC 策略、本地测试页面）；5 项单元测试和 JS 静态检查通过。**真实 Chrome 端到端验证尚未完成，不是稳定版。**  
**V0.2：** 最小 Chrome 扩展原型 + 位置权限控制。  
**V0.3：** WebRTC 隐私设置与测试、恢复操作、兼容性报告。  
**未来：** 只有明确用户需求和可靠实测证据后，再评估 Edge / Firefox 支持。

**项目原则：功能少、效果可测、容易理解、可以回滚。**
