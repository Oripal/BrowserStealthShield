# BrowserStealthShield 项目定位与路线图 V0.2

**更新日期：2026-10-18**  
**项目名称：BrowserStealthShield**  
**英文描述：Browser Privacy & Isolation Diagnostic Toolkit**  
**中文描述：浏览器隐私与隔离诊断工具箱**

## 1. 背景与转型理由

项目早期以浏览器字体枚举及 API 修改作为实验起点，尝试降低某些特征可见性。研究显示“减少某项检测值”与“改善隐私”不是等价命题，修改原生 API 可能额外影响功能、稳定性与数据一致性。现将项目转为可重复验证的隔离与隐私工程研究。

**核心使命：帮助开发者正确理解浏览器隔离边界，在获得用户授权的环境中诊断隐私暴露、配置错误与兼容性风险。**

**项目不做：** 伪造区域/身份、绕过平台反欺诈或封禁、在未经授权的网站上开展探测、清除安全日志、声称任何测试分数可保证账号不受限。

## 2. 用户与典型场景

- 多工作区开发者：检查工作/私人浏览环境是否混用站点数据。
- QA 与安全工程师：复现 Chrome Profiles、Firefox Containers 和隐私功能的行为差异。
- 组织 IT / 运维人员：检查浏览器政策有效性、扩展权限与潜在配置冲突。
- 桌面 AI 工具开发者：分别审查浏览器、CLI 与 IDE 的网络连接配置，不把浏览器测试外推至本机所有进程。

## 3. 四层分析模型

| 层级 | 研究范围 | 局限性 |
|---|---|---|
| L1 会话与存储 | Cookie、LocalStorage、IndexedDB、Cache Storage、Service Worker | 隔离不自动改变硬件或网络环境 |
| L2 浏览器与设备 | Canvas、WebGL、AudioContext、字体、语言及浏览器 API | 不能以指纹值推断平台内部风控结论 |
| L3 网络与传输 | WebRTC、IP、DNS、IPv6、代理与进程差异 | 浏览器扩展不等于系统网络抓包或全局审计 |
| L4 账号与服务政策 | 身份、授权、服务条款等概念边界 | 不访问、推测或模拟第三方私有风控系统 |

## 4. 功能路线

### A. Isolation Lab（优先级 P0）
- 在项目自控测试页面生成**临时、非敏感**的测试键。
- 逐项记录在独立 Profile / Container 之间的可见性。
- 输出带环境信息的可复现实验表；测试结束后提供数据清理。
- 不读取或导出真实网站的 Cookie、账号数据和认证信息。

### B. Fingerprint Observatory（优先级 P1）
- 用户主动触发时，观察公开 API 的可见特征及其变化。
- 区分“浏览器原生输出”“隐私设置干预”与“原因待查”，不宣称可识别用户实际位置。
- 优先显示摘要和差异，不上传原始唯一指纹；允许本地清除结果。
- 不使用修改 Function.prototype.toString 等欺骗性手段作为默认功能。

### C. Network Path Audit（优先级 P1–P2）
- 浏览器范围内的 WebRTC/IP 诊断必须说明测试前提和信息暴露范围。
- CLI/IDE 检查由用户主动执行的独立工具承担；最初仅检查明确支持的网络设置和状态。
- 避免依赖网络钩子、扫描无关局域网主机或无授权访问外部系统。
- 实验和测量结果不能代替外部服务商政策解释。

### D. Configuration Inspector（优先级 P2）
- 提供 Chrome / Edge / Firefox 有效策略的**只读核对流程**。
- 明示适用版本、策略作用范围与冲突风险。
- 如果未来实现可选修改功能，须有预览、确认、备份、回滚和功能回归测试。

## 5. 最小可行版本定义（MVP）

MVP **不是“能隐藏指纹的插件”**，而是：**在用户自控页面上完成两种浏览器隔离方式的实际对照，形成可复现的结构化报告。**

验收标准：
1. 在同版本、同设备、同网络条件下，至少完成两个 Chrome Profile、两个 Firefox Container 的站点数据隔离验证。
2. 每次报告包含实验输入、浏览器版本、观察结果、复测次数和已知局限；实验之前不填充“实测结果”。
3. 测试只使用临时随机标识；不采集真实服务账号凭证、会话令牌或敏感本地路径。
4. 测试所需权限最少，用户能退出并清除本地实验数据。
5. 任何失败都有明确错误说明，不以“检测分数归零”作为通过标准。

## 6. 工程实施阶段

| 阶段 | 交付物 | 发布门槛 |
|---|---|---|
| **0 研究** | README、V2.0 长文、主张审计、测试设计 | 信息明确标注是否已验证 |
| **1 隔离实验** | 自有测试页面、跨 Profile/Container 用例、报告模板 | 能在指定浏览器版本复现 |
| **2 诊断面板** | 本地只读 UI 与最小权限扩展候选 | 通过功能、权限与无障碍测试 |
| **3 系统诊断（可选）** | 独立 CLI / 策略检查、回滚指南 | 不执行破坏性操作；明确支持范围 |

## 7. 历史原型处理原则

原始 CJK 相关 Hook、语音列表过滤、全局原生函数覆盖等方案保留为**审计背景**，不作为默认产品能力或安全保证。若以后公开研究性复现代码，须在隔离测试环境、明确标记不适合生产使用，并与正式工具区分。

## 8. 文章与仓库如何分工？

文章重点回答**为什么多 Profile 不等于多设备、浏览器指纹为什么可能产生误判、客户端网络差异意味着什么**。仓库重点提供**资料、可复现测试、工具设计与验证结果**。两者均不承诺规避任何第三方平台的反欺诈与账号规则。
