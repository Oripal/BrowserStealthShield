# BrowserStealthShield — 地理位置隐私测试计划 V0.1

**测试状态：控制逻辑的 5 项单元测试和 JavaScript 语法检查已通过；真实 Chrome 浏览器端到端测试尚未完成。以下步骤仍是待执行的实际验收方案。**

## 测试环境记录

记录浏览器名称和版本、操作系统版本、位置权限初始状态、WebRTC 策略初始状态，以及网络场景（不记录可识别个人的出口 IP）。只在自有或经授权的测试页面进行。

## 实验 A：Geolocation API 权限控制

1. 记录浏览器现有的位置权限状态（允许 / 询问 / 阻止）。
2. 在用户主动授权后，使用浏览器原生内容设置改为阻止。
3. 从自有 HTTPS 测试页面发起一次定位请求，确认页面不能获得精确经纬度，正确处理权限拒绝。
4. 通过界面恢复原设置，确认设置状态正确；必要时验证原本获授权的网站仍正常工作。
5. 不记录经纬度或其他识别个人的信息。

## 实验 B：WebRTC 地址暴露与功能兼容性

1. 先读取并记录 WebRTC IP 处理策略，作为原始对照。
2. 由用户主动开始自有 WebRTC ICE 测试，记录候选地址类别与是否发现非预期地址，输出需脱敏。
3. 用户可选择启用 Chrome 提供的受限 IP 处理策略并再次测试。
4. 检查视频会议、语音和点对点应用是否出现连通性问题；提供恢复原策略的方法。
5. 不把单一 ICE 测试结果外推为“所有网络协议和所有站点都无法获知 IP”。

## 实验 C：出口 IP 与精确位置的边界

1. 说明 HTTPS 服务器正常情况下可以观察访问连接的公网 IP。
2. 在用户明确同意的情况下，使用自有测试服务验证服务器侧可见的是出口 IP；**不上传该值到公开实验报告**。
3. 区分 IP 地区推断与需要权限才能获得的精确 Geolocation API 位置。
4. 测试结束删除任何临时日志，并在报告中明确：扩展本身不能消除服务器对出口 IP 的观察。
